# Lego AI - project guide for Claude Code

## What this project is
Build a brand-new AI made only for LEGO Technic. Real instruction booklets are translated into a build language (exact part-to-hole moves + what each part does + why). A small AI is trained from scratch on that language, then learns to design its own working builds. Booklets for its designs are drawn by LDraw + LPub3D, not by the AI.

Owner: Dennis. Wants plain language, no jargon, straight to the point.

## Layout
```
sets/<set>/                    one folder per instruction booklet
  booklet.pdf, parts_list.csv  the booklet and its official parts list (answer key)
  mechanisms.json              each mechanism as a chain of parts in motion order, with roles; confirmed/hypothesis
  systems.json                 the machine's systems (real-world meaning, purpose, depends/feeds) and every part's role in them; open questions
  booklet_map.csv              every step in booklet order: folder, build (main/side build), page, where a side build attaches
  steps/<build>-NN/            one folder per step, e.g. main-18, seat-03, arm-05
    picture.png                the step cropped from the booklet
    annotation.json            the labeled step (format: docs/labeling_instructions.md)
    notation.tbl               the step in the build language
  training.jsonl, training.tbl, preview.md, part_matches.csv, roles.csv   GENERATED by tools/build_set.py, don't hand-edit
catalog/technic_parts.csv      every Technic part (Rebrickable) + size, thickness, part_type, friction, function, point counts, gear teeth, description
catalog/mechanisms.json        library of mechanism types: what they do, roles, rules, how they fail
catalog/connections.csv        every named point per part (hole1, axle2...): type, position + direction (holes), depth, slide, how it turns
docs/                          labeling_instructions.md, framework.md, detail_spec.md, mechanism_training.md (what the data teaches + training tasks) (every level of detail: conventions, status, what to add next)
tools/mechanisms.py            per-step mechanism state, motion (turn ratios), builds-on chains, JAM check
tools/build_set.py             step folders -> training files (adds MECH/STATE/MOTION lines + answer.mechanism);  tools/check_steps.py  checks training.jsonl
```
- Every annotation gets `big_picture` per new part (system, role, real machine, every later step that uses it) from systems.json + notation. A part without a role is reported by build_set.py: fix it.
- Step folders are the source of truth. Side-build notation files hold only their own lines; build_set.py wraps them in GROUP ... END before the main step's `ATTACH <build>` line.
- Live docs: Build Language https://claude.ai/artifact/TXzA7joTEvVGAZ2y94mvUw, Framework https://claude.ai/artifact/9agc7uxAr16TjJK2EYirj4

## Build language (short)
STEP n | ADD name partnum color | CONNECT a.point -> b.point LOCKED|TURNS|STIFF [DEPTH n] | ANGLE name deg | MESH a.teeth b.teeth | GROUP g ... END / ATTACH g | DOES a VERB b (HOLDS, CARRIES, SPINS_ON, DRIVES, LOCKS, SUPPORTS) | RATIO a b x/y | PATTERN name | MECH id type part role | STATE id n/m [COMPLETE] | MOTION input part=turns... | REQUEST ...
- MECH / STATE / MOTION lines are generated by build_set.py from mechanisms.json; never hand-write them in notation.tbl.
- Points are the catalog's point names for that part (catalog/connections.csv): hole1..N (round pin holes), axlehole1..N (cross holes), pin1..N and axle1..N (one stop per hole-length of a pin or axle), barhole/bar (3.2 mm). Numbered along the part's longest direction. Plus `teeth` for MESH.
- `axle-A.axle2 -> beam-C.axlehole1` = the axle's 2nd hole-length sits in the beam's cross hole. Depth = the shorter of the two points (e.g. 0.5 in a half bush); write DEPTH only when pushed in less than that.
- LOCKED = cross in cross (turn together); TURNS = axle in round hole or frictionless pin; STIFF = friction pin in round hole. tools/check_notation.py checks the point exists, the two fit, and the word is right.
- `?` = point not shown in the booklet (open). `~` after a point (`hole3~`) = best reading of the picture, not confirmed: named and checked, counted as estimated. `#` = note for people, stripped before training.
- Names are permanent (pin-L, gear-3, beam9-X). Only part numbers from the set's parts list.
- build_set.py turns each step's CONNECT lines into a `joins` list in the annotation (points, point types, depth, fit, exact yes/no).

## How to label a new set
1. Make sets/<set>/ with booklet.pdf and parts_list.csv (Rebrickable inventory); write booklet_map.csv.
2. Per step: crop the picture (PyMuPDF) into steps/<build>-NN/picture.png; look ahead in the booklet to confirm what later steps use it for.
3. Write annotation.json AND notation.tbl.
4. Run `python tools/build_set.py sets/<set>`, `python tools/check_steps.py sets/<set>/training.jsonl sets/<set>/parts_list.csv` and `python tools/check_notation.py sets/<set>/training.tbl`; fix anything listed. Every part in the parts list should be used exactly once by the end.
5. Flag anything the picture doesn't show (needs_review + review_note, `?` in the notation).
